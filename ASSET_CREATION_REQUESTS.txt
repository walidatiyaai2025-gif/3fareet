3FAREET — EXTERNAL ASSET CREATION POLICY & REQUEST QUEUE
=========================================================
Policy ID: AFA-POL-ASSET-001
Status: ACTIVE / MANDATORY
Scope: ALL programmers, AI agents, designers, technical artists, integrators and reviewers working in this repository.
Canonical missing-asset status registry: docs/MISSED_ASSETS.md
This root file is the operational handoff queue for assets that cannot be completed safely by repository code alone.

PROGRAMMING CLOSURE MODE
------------------------
Effective immediately, until the project owner explicitly says to resume visual polish / asset production:
1. PRIORITY = close programming, validation, integration, tests, CI, runtime contracts and gameplay defects.
2. DO NOT spend engineering time polishing visuals when a programming task can be closed instead.
3. If code requires a missing external asset, DO NOT fabricate a fake production asset and DO NOT weaken a production gate.
4. Record the missing asset in THIS ROOT FILE before or in the same commit/PR that introduces or discovers the dependency.
5. Continue coding against a clearly labelled review/blockout/fallback path only when the existing gate explicitly permits it.
6. Production/owner-acceptance state must remain false until the real asset is delivered and verified.
7. Never mark P1 VERIFIED, close an asset defect, merge a production gate, or publish because a review/blockout asset exists.

MANDATORY RULE FOR EVERY PROGRAMMER / AI AGENT
----------------------------------------------
If you discover any asset that cannot be created correctly by code in this repository, you MUST add or update an entry in this file with ALL of these fields:
- REQUEST ID
- RELATED TASK / UART / ISSUE
- ASSET NAME
- WHY CODE ALONE IS NOT ENOUGH
- REQUIRED TOOL
- SOURCE / REFERENCE INPUTS
- TARGET SOURCE PATH
- TARGET EXPORT PATH / FORMAT
- CREATION PROMPT (ready to copy/paste into the named tool/assistant)
- SCRIPT / PROCEDURE (exact high-level steps or script filename expected)
- ACCEPTANCE CRITERIA
- MOBILE / PERFORMANCE BUDGET
- PROVENANCE REQUIREMENTS
- CURRENT STATUS

No entry = no untracked external-asset dependency.

STATUS VALUES
-------------
REQUESTED -> IN_CREATION -> REVIEW -> READY_FOR_INTEGRATION -> INTEGRATED -> VERIFIED
Use BLOCKED if source/reference/license/owner approval is missing.

PROVENANCE POLICY
-----------------
- Generated/review/blockout/refinement assets MUST be labelled as such.
- A generated or procedural asset MUST NOT be silently promoted to final production art.
- Editable source must be preserved where practical (.blend/.svg/.kra/.psd/.wav project/etc.).
- Exported runtime asset must be reproducible from the editable source.
- Do not use copyrighted real-world vehicle branding/logos or unlicensed commercial assets.
- Every final source must have stable ownership/licensing and a documented source path.
